# Полный ручной план проверки Market KG

Этот план проверяет публичный каталог, регистрацию, все роли, управление каталогом, изображения, многопоставочный заказ и разграничение доступа.

## 0. Подготовить чистый стенд

Откройте PowerShell в корне проекта:

```powershell
docker compose up -d --build
docker compose exec backend python -m scripts.seed
docker compose ps
```

Во втором терминале:

```powershell
Set-Location apps/frontend
npm.cmd run dev
```

Проверки доступности:

- `http://localhost:8001/health` показывает `{"status":"ok"}`;
- `http://localhost:3000` открывает Market KG;
- `http://localhost:3000/catalog` показывает 12 товаров.

## 1. Правильно открыть три роли

Не открывайте ADMIN, SUPPLIER и SHOP в трёх обычных вкладках одного профиля Chrome. Вкладки разделяют cookie, поэтому вход одной роли может повлиять на обновление сессии другой роли.

Рекомендуемая схема:

| Окно | Режим | Роль |
| --- | --- | --- |
| A | обычный Chrome | ADMIN |
| B | Chrome Incognito или отдельный профиль Chrome | SUPPLIER |
| C | Edge InPrivate или третий профиль Chrome | SHOP |

Если доступен только один профиль браузера, проверяйте роли последовательно и каждый раз нажимайте «Выйти».

Общий пароль demo-аккаунтов: `MarketKG2026!`.

## 2. Проверить гостевой каталог

До входа откройте `http://localhost:3000/catalog`.

- [ ] Заголовок показывает 12 позиций.
- [ ] Карточки имеют название, цену, MOQ, остаток, поставщика и изображение.
- [ ] Фильтр «Дордой» оставляет товары поставщиков Дордоя.
- [ ] Фильтр «Кара-Суу» оставляет товары «Береке Хозтовары».
- [ ] Категория «Напитки» показывает воду и чай.
- [ ] Поиск `DEMO-005` находит средство для мытья посуды.
- [ ] «Только в наличии» не вызывает ошибку.
- [ ] «Сбросить» возвращает все 12 товаров.
- [ ] Открытие карточки показывает описание, MOQ, остаток и поставщика.
- [ ] Гость вместо покупки видит предложение войти.


- [ ] «Товары» показывает 12 товаров.
- [ ] «Поставщики» показывает 3 поставщиков.
- [ ] «Категории» показывает 6 категорий.
- [ ] «Заказы» содержит `DEMO-ORDER-001`.

## 5. ADMIN — категории

Откройте `/admin/categories`.

Создайте категорию:

| Поле | Значение |
| --- | --- |
| Название | `QA Категория` |
| Slug | `qa-category` |
| Родитель | `Корневая категория` |

- [ ] Категория появляется в списке.
- [ ] Измените название на `QA Категория обновлена` и сохраните.
- [ ] Изменённое название остаётся после обновления страницы.
- [ ] Удалите категорию — пустая категория удаляется.
- [ ] Попытка удалить категорию «Напитки» возвращает понятную ошибку, потому что в ней есть товары.

## 6. ADMIN — поставщики

Откройте `/admin/suppliers`.

Для «Алтын Дистрибьюшн»:

- [ ] Измените описание, нажмите «Сохранить» и обновите страницу.
- [ ] Верните исходное описание: `Напитки, бакалея и товары ежедневного спроса.`
- [ ] Нажмите «Отключить» и подтвердите предупреждение.
- [ ] Проверьте, что товары поставщика исчезли из публичного каталога.
- [ ] Нажмите «Включить» и проверьте, что товары вернулись.

Создание нового поставщика можно проверить отдельно. Такой профиль без связанного SUPPLIER-аккаунта управляется только администратором; удаление поставщиков намеренно заменено мягким отключением.

Используйте записанный номер заказа.

### Поставщик A

Войдите как `supplier.demo@market.kg`.

- [ ] Заказ содержит только «Минеральная вода 1 л».
- [ ] Нет товаров B/C и полного адреса магазина.
- [ ] Переведите часть заказа: `Ожидает → Принят → Сборка → Готов`.

### Поставщик B

Выйдите и войдите как `supplier-b.demo@market.kg`.

- [ ] В заказе видно только средство для мытья посуды.
- [ ] Пройдите статусы до «Готов».

## 11. ADMIN — завершить общий заказ

Вернитесь в окно A и обновите `/admin/orders`.

- [ ] Новый заказ найден по записанному номеру.
- [ ] Видны три поставщика и три отдельных статуса «Готов».
- [ ] Видны адрес, телефон, способ оплаты, товары, доставка и итог.

Последовательно выполните:

```text
Новый
→ Подтверждён
→ Сборка
→ Готов к доставке
→ В доставке
→ Доставлен
```

- [ ] После каждого действия заголовок показывает новый статус.
- [ ] После «Доставлен» кнопки перехода исчезают.
- [ ] Повторный или обратный переход недоступен.

## 12. SHOP — проверить результат

Вернитесь в окно C и откройте `/orders`.

- [ ] Заказ отображается со статусом «Доставлен».
- [ ] В деталях видны все три товара.
- [ ] Суммы и снимки цен не изменились после редактирования каталога.
- [ ] Адрес и способ оплаты совпадают с checkout.

## 13. Мобильная проверка

В Chrome DevTools включите ширину около 390 px.

- [ ] Каталог не имеет горизонтальной прокрутки.
- [ ] Фильтры открываются как мобильная панель и закрываются клавишей Escape/кнопкой.
- [ ] Корзина и checkout помещаются по ширине.
- [ ] Меню ADMIN и SUPPLIER открывается кнопкой и закрывается.
- [ ] Таблица заказов превращается в читаемые карточки.

## 14. Финальная очистка

После проверки верните чистый demo-набор:

```powershell
docker compose exec backend python -m scripts.seed
```

Команда удалит временные товары и заказы demo-магазинов, восстановит цены, остатки, изображения и `DEMO-ORDER-001`. Аккаунт `qa-shop.demo@market.kg` также будет удалён. Созданный вручную поставщик без demo-владельца не удаляется — его следует оставить отключённым или не создавать при основной проверке.

## Критерий успешной проверки

Проект прошёл этап 1, если:

- все роли входят и попадают в правильный интерфейс;
- роли не получают доступ к чужим разделам;
- каталог и изображения отображаются;
- товар можно создать и изменить;
- SHOP оформляет многопоставочный заказ;
- каждый SUPPLIER видит только свою часть;
- ADMIN видит полную картину и завершает доставку;
- SHOP видит финальный статус и неизменяемые снимки заказа;
- после ошибок данные не пропадают и интерфейс показывает понятное сообщение.
