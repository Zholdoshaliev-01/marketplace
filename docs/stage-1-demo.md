# Этап 1: демонстрационный стенд Market KG

Полный сценарий ручной проверки с конкретными значениями полей находится в `docs/manual-qa-plan.md`.

## Запуск

Из корня проекта:

```powershell
docker compose up -d --build
docker compose exec backend python -m scripts.seed
```

В отдельном терминале:

```powershell
Set-Location apps/frontend
npm.cmd run dev
```

Открыть `http://localhost:3000`. Общий пароль всех demo-аккаунтов: `MarketKG2026!`.

## Demo-аккаунты

| Роль | Организация | Email |
| --- | --- | --- |
| ADMIN | Market KG | `admin.demo@market.kg` |
| SHOP | Магазин У дома, Бишкек | `shop.demo@market.kg` |

| SHOP | Народный магазин, Ош | `shop-c.demo@market.kg` |
| SUPPLIER | Алтын Дистрибьюшн, Дордой | `supplier.demo@market.kg` |

Обычная публичная регистрация всегда создаёт роль `SHOP`. Аккаунты `ADMIN` и `SUPPLIER` не создаются через публичную форму — для этапа 1 их создаёт безопасный development seed.

## Что находится в базе

- 3 магазина;
- 3 поставщика, каждый связан со своим SUPPLIER-аккаунтом;
- 6 категорий;
- 12 активных товаров с локальными demo-изображениями;
- зона доставки «Бишкек» стоимостью 200 сом;
- заказ `DEMO-ORDER-001` с товарами трёх поставщиков;
- отдельный fulfillment для каждого поставщика.

## Проверка роли SHOP

1. Войти как `shop.demo@market.kg`.
2. Открыть каталог и проверить фильтры по категории, поставщику, рынку, цене и наличию.
3. Добавить товары минимум двух поставщиков с учётом MOQ.
4. Открыть корзину и перейти к оформлению.
5. Указать город `Бишкек`, телефон и адрес, выбрать оплату.
6. Оформить заказ и проверить его в разделе «Заказы».

Backend повторно проверяет цены, MOQ и остатки, рассчитывает доставку, уменьшает остатки и создаёт отдельную часть заказа для каждого поставщика.

## Проверка роли SUPPLIER

1. Войти одним из supplier-аккаунтов.
2. В «Мои товары» изменить цену или остаток.
3. Создать новый товар, выбрав категорию, SKU, цену, MOQ и остаток.
4. Открыть редактирование товара.
5. В блоке «Изображения» добавить URL, изменить порядок или удалить изображение.
6. В «Выполнение заказов» открыть заказ и пройти статусы `Ожидает → Принят → Сборка → Готов`.

Поставщик видит только собственные товары и позиции заказа. Адрес покупателя и товары других поставщиков ему не возвращаются.

Изображения на этапе 1 работают по URL. Можно использовать локальный адрес, например:

```text
http://localhost:3000/images/products/drinks.svg
```

Загрузка файла с компьютера в object storage относится к следующему этапу.

## Проверка роли ADMIN

Войти как `admin.demo@market.kg`.

- «Заказы»: все заказы, разбивка по поставщикам, общий статус доставки;
- «Товары»: создание карточки от имени поставщика, изменение цены, MOQ, остатка, описания и изображений, снятие с продажи;
- «Поставщики»: создание и редактирование профиля, рынок, павильон, активность;
- «Категории»: создание корневых и дочерних категорий, переименование и безопасное удаление;
- «Обзор»: показатели заказов и быстрые переходы к операциям.

Созданный администратором поставщик без `owner_user_id` управляется только администратором. Для входа поставщика нужен связанный SUPPLIER-аккаунт; в demo-наборе такие связи уже созданы.

## Повторный сброс demo-данных

```powershell
docker compose exec backend python -m scripts.seed
```

Seed удаляет и пересоздаёт только demo/старые pilot-записи. Обычные зарегистрированные пользователи и не-demo данные не удаляются.

Не используйте demo-пароль и seed в production.
